# DOM XSS in statistics window chart renderer via unencoded chart data

**ID:** vuln-0007
**Severity:** LOW
**Found:** 2026-11-06 22:20:38 UTC
**Target:** /workspace/electron/usage-stats.html
**Endpoint:** electron/usage-stats.html (chart renderer)
**Method:** N/A
**CWE:** CWE-80
**CVSS:** 2.5
**Confidence:** High
**Fix Effort:** Low

## Description

The statistics window builds its chart by assigning an HTML template string to chart.innerHTML, interpolating row.date into a title attribute and into element text without encoding. The window runs with nodeIntegration true, and its CSP allows unsafe-inline.

## Evidence

Headless Chromium with a hostile row.date: row attribute names came back as ["class","title","x","onclick","a"] with getAttribute(onclick) equal to alert(1). With the fix applied the same input yields only ["class","title"] and the payload stays literal text. A CSP test on the page policy confirmed inline event handlers still execute.

## Impact

Confirmed: markup and attribute injection into the statistics document. An attacker-influenced value becomes a real event-handler attribute rather than text. Because the window has nodeIntegration enabled, script executed there can reach require; that step was not exercised.

## Counterevidence

Checked for constraints: countFrom() coerces count to a number so the entry point is row.date; row.date is normally a locally generated ISO day string; the injected onclick on a div needs a click. The page CSP was tested and does not block inline handlers, and the window has nodeIntegration true, so no control exists at the sink.

## What Would Change This Severity

Evidence that the counter response is attacker-influenceable, or a second in-page script primitive in this window, would raise this to critical given nodeIntegration is enabled.

## Technical Analysis

telemetry.js loadDailyCounts builds rows as date plus countFrom(results[i]); countFrom coerces count to a number, but date passes through. usage-stats.html load() then assigns an HTML template to chart.innerHTML at lines 212-220, interpolating row.date into a double-quoted title attribute (line 216) and into element text (line 218), and row.count into the same attribute. No encoding or textContent is used anywhere in the template, so the HTML parser interprets the values. A value containing a double quote closes the attribute and a following name=value becomes a new attribute on the row element. telemetry.js openStatsWindow creates the window with nodeIntegration true and contextIsolation false, and the page CSP is default-src self unsafe-inline with no script-src, which was tested and does not block inline handlers.

## Remediation

Replace the innerHTML string template with programmatic DOM construction so every value is assigned through a property that is not an HTML parser: set the row date and count through the title property, the tick label through textContent, the bar height through style.height, and the today marker through className. Remove the innerHTML assignment entirely.

## Fix Verification

Gates, in order.

1. Applicability. fix_before is the verbatim byte content of electron/usage-stats.html lines 211-220 including the file's CRLF endings, confirmed by splitting the file on CRLF and by od -c. start_line and end_line cover exactly that span.

2. Security closure. Applied the replacement to a copy of the file and re-ran the page in headless Chromium with the hostile row.date. Before the fix the row carried the attribute list class, title, x, onclick, a with onclick equal to alert(1). After the fix it carries only class and title, with the hostile value stored verbatim in title. The replacement never assigns an interpolated string to innerHTML; every value goes through textContent or through title, className and style.height property assignment, none of which are HTML parsers.

3. Bypass review. Re-read the diff independently and traced the sibling paths: row.date also feeds fmtDay and now reaches tick.textContent; row.count reaches col.title and the numeric bar.style.height; isToday only controls className. Re-grepped the file for innerHTML, outerHTML, insertAdjacentHTML and document.write and none remain. Tried three alternate malicious input classes against the fixed code: a bare double quote, an img tag with an onerror handler, and a JS-call style string. All render as inert text.

4. Preserved behaviour. After the fix all three rows still render, col and col-today classes are correct, each row keeps a title of the form date colon count, bars keep their height in pixels, ticks keep the MM/DD label, the i %% 3 check is unchanged, and the status line still updates. max is still computed from data.rows so bar sizing behaves identically.

5. Repository checks. The electron directory has no test suite or linter configured. Extracted the page's inline script and compiled it under Node with new Function: syntax OK. A browser integration test does not exist in the repository, so that remains a reason-only gap.

## Assumptions

Requires either attacker influence over a value the chart renders, or an existing in-page script primitive in this window.
