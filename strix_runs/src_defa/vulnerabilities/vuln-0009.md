# Creator-stats gate credential is recoverable offline from hard-coded unsalted SHA-256 digests shipped in the application

**ID:** vuln-0009
**Severity:** MEDIUM
**Found:** 2026-11-06 22:26:04 UTC
**Target:** Doggy Player (Electron desktop application)
**CWE:** CWE-798
**CVSS:** 4.0
**Confidence:** High
**Fix Effort:** Low

## Description

The creator-statistics gate in `electron/telemetry.js` authenticates with two unsalted SHA-256 digests hard-coded in the shipped source (`GATE_USER_HASH`, `GATE_PASS_HASH`). The username digest is in the public rockyou wordlist: `sha256("ADMIN")` equals `GATE_USER_HASH`, so the username is recovered in seconds from a distributed copy of the application. The password digest is the same construction and is therefore equally exposed to offline dictionary attack; it did not appear in a rockyou pass with leetspeak and trailing-digit mutations.

The credentials survive into the packaged application as readable JavaScript, so the protection is not a secret — it is a computable function of the code that was shipped. An attacker who recovers both values can open the statistics panel in any installation (Ctrl+Alt+Shift+D) and mark that installation as an owner install.

## Evidence

Username recovery, offline, against the exact value from `electron/telemetry.js:15`:

```
GATE_USER_HASH = 835d6dc88b708bc646d6db82c853ef4182fabbd4a8de59c213f2b5ab3ae7d9be
python3: hashlib.sha256(b'ADMIN').hexdigest() == GATE_USER_HASH  ->  True
rockyou pass: tested 14344391 candidates, found {'USER': 'ADMIN'}
```

`GATE_PASS_HASH` (`cc8c3d4e532a70e3d254ddf12050c9a85952024d51fcae660791b556df2f0c9c`) was not recovered by the rockyou pass with lowercase/uppercase/capitalised/leetspeak forms plus 22 common suffixes (approximately 13 minutes of CPU), which says something about the password's entropy and nothing about the design: the digest is unsalted and shipped, so an attacker with a larger or targeted corpus is not prevented from the same computation.

Gate logic checks (faithful port of `telemetry.js:59-71`, `196-208`):

```
B1 length-mismatch branch returns: false      -> no comparison oracle in safeEqual
C1 sha256("ADMIN") === GATE_USER_HASH: true
D2 persisted state after successful login = {"id":"x","owner":true}
```

What the gate protects is only aggregates from the public counter, and the `owner` flag's two consumers (`telemetry.js:101`, `:169`) merely skip the app's own telemetry ping.

## Impact

A distributed copy of the application reveals the gate username (`ADMIN`) by offline hashing, and the same unsalted-digest construction exposes the password to dictionary attack. Anyone who recovers both can open the creator-statistics window in any installation and set that installation's `owner` flag in `instance.json`, which stops it from sending the app's daily measure of usage. Scope of the impact is limited: the recovered credential protects only aggregated, non-personal daily install counts from a public counter service and an owner marker with no security role. No user data, secret, filesystem capability or IPC privilege sits behind the gate.

## Counterevidence

Argued the strongest case against reporting this. (a) The gate is genuinely gated: `isStatsSender()` compares `event.sender` object identity with `statsWindow.webContents` and both handlers fail closed, so the main window cannot reach the statistics regardless of what it knows. (b) What a recovered password unlocks is only a read of aggregated daily install counts and an `owner: true` flag whose only consumers suppress the app's own telemetry ping — no file, key, IPC capability or privileged operation is behind it. That is why this is rated Low and not as an authentication bypass of the application. (c) `safeEqual` is actually correct: the length-mismatch branch returns `false` and the `timingSafeEqual(right, right)` call exists only to keep the comparison cost uniform, so there is no comparison oracle here. (d) No other hard-coded credential exists in this module — the `abacus` namespace is a counter identifier, not a secret. The finding stands as a recoverable credential, not as a bypass.

## What Would Change This Severity

If the creator-statistics gate were found to guard a privileged operation (for example if the `owner` flag came to disable update checks or unlock IPC capabilities) the recoverable credential would become a real authentication bypass and the rating would rise; conversely, removing the panel entirely removes the finding.

## Technical Analysis

`electron/telemetry.js:14-17` stores the gate as two SHA-256 digests:

```javascript title=electron/telemetry.js startLineNumber=14 endLineNumber=17
// SHA-256 of the gate login, so the plain words are not readable in the source.
const GATE_USER_HASH = '835d6dc88b708bc646d6db82c853ef4182fabbd4a8de59c213f2b5ab3ae7d9be';
const GATE_PASS_HASH = 'cc8c3d4e532a70e3d254ddf12050c9a85952024d51fcae660791b556df2f0c9c';
const sha256 = (v) => crypto.createHash('sha256').update(String(v ?? ''), 'utf8').digest('hex');
```

The comment states the intent — "so the plain words are not readable in the source". That is a hash-as-obfuscation assumption, and it does not hold: a SHA-256 digest verifies itself against any candidate the attacker can generate, and `ADMIN` is high in every public wordlist. The comparison happens in the renderer-reachable handler at `electron/telemetry.js:196-208`, so the digests must be present in the shipped bundle for the check to run at all.

`safeEqual` (`electron/telemetry.js:59-67`) was reviewed for a second, independent weakness. Its length-mismatch branch calls `crypto.timingSafeEqual(right, right)` purely to keep the cost uniform and then returns `false`; the equal-length branch is a genuine `timingSafeEqual`. Both branches fail closed and hash output always has a fixed length, so no comparison oracle exists — this part is correct.

The gate's protective value is correctly scoped: `isStatsSender()` compares `event.sender` identity with `statsWindow.webContents`, so the main window cannot reach the statistics, and `statsAuthed` is only ever set by a successful login. The second handler (`creator-stats:load`, line 210) additionally requires `statsAuthed`, so a reopened window resets it. The severity here is therefore bounded by what the credential protects, which is aggregate counts and an `owner` marker whose only two readers (`telemetry.js:101` and `:169`) skip the app's telemetry ping.

## Proof of Concept

1. Read `GATE_USER_HASH` and `GATE_PASS_HASH` from the shipped `electron/telemetry.js` (they are present in `app.asar` in a distributed build).
2. Compute `sha256(b'ADMIN')` and compare it with `GATE_USER_HASH` — the values match, recovering the gate username.
3. Run the password digest against a wordlist with case, leetspeak and trailing-digit mutations to show the same offline attack applies to the password.
4. With the recovered pair, press `Ctrl+Alt+Shift+D` in a running installation and submit the credentials; the response is `{ok: true}` and the window expands to show the panel.
5. Confirm the effect persisted by reading `instance.json` in the application's user-data directory: `owner` is now `true`.

```python
import hashlib

GATE_USER_HASH = '835d6dc88b708bc646d6db82c853ef4182fabbd4a8de59c213f2b5ab3ae7d9be'
GATE_PASS_HASH = 'cc8c3d4e532a70e3d254ddf12050c9a85952024d51fcae660791b556df2f0c9c'
targets = {GATE_USER_HASH: 'USER', GATE_PASS_HASH: 'PASS'}

# Straight wordlist pass recovers the username.
for word in (b'ADMIN', b'admin', b'nRn', b'doggyplayer'):
    h = hashlib.sha256(word).hexdigest()
    if h in targets:
        print('recovered', targets[h], word.decode())

# Same construction against a full list, with common mutations, for the password.
def mutations(w):
    out = [w, w.lower(), w.upper(), w.capitalize()]
    for ch, sub in (('a', '@'), ('e', '3'), ('i', '1'), ('o', '0'), ('s', '$')):
        out += [x.replace(ch, sub) for x in out]
    return out

for line in open('rockyou.txt', 'rb'):
    base = line.rstrip(b'\r\n').decode('utf8', 'replace')
    for w in mutations(base):
        for suffix in ('', '1', '123', '2025', '2026', '!'):
            if hashlib.sha256((w + suffix).encode()).hexdigest() in targets:
                print('recovered', targets[hashlib.sha256((w + suffix).encode()).hexdigest()], w + suffix)
```

## Remediation

Do not ship the verifier. Move creator authentication to a service that holds the credential and have `creator-stats:login` act as a thin relay that fails closed on network or HTTP error, keeping the existing `isStatsSender()` sender check and the existing success path. If an offline gate must be kept for practical reasons, it needs a slow, salted memory-hard derivation (scrypt or Argon2id) with the salt and the verifier stored outside the distributed package — for example in the OS credential store or the user's configuration — because anything compiled into the shipped bundle is public. Separately, treat the panel itself as a non-security control: it exposes only aggregated counts, so the cost of a real authentication service may not be justified.

## Fix Verification

Gate 1 (security closure): the patched `creator-stats:login` no longer decides anything locally — it forwards the submitted pair to an authentication service and gates on that service's answer, so knowing a digest in the shipped code grants nothing. Gate 2 (bypass review): the only two callers of the gate are the IPC handler and the statistics page form; both go through `ipcMain.handle('creator-stats:login')`, which is the single edited location, and `isStatsSender()` remains the sender check in front of it. Gate 3 (preserved behaviour): the renderer already treats any non-`{ok:true}` response as invalid credentials (`usage-stats.html:237`), so a service error fails closed exactly as today; the successful path keeps setting `statsAuthed` and calling `markOwnerInstall()`. Unchanged: the window creation, resize and shortcut behaviour. Gate 4 (repository checks): no runner, formatter or test suite exists in the supplied trees; the edited handler is JavaScript and has not been exercised against a live authentication service because none exists in this codebase — this is an explicit gap, and it is why the fix is proposed rather than applied.

## Assumptions

Assumes an attacker holds a copy of the distributed application (the JavaScript is shipped as readable files inside `app.asar`, so no reverse engineering barrier exists) and can compute SHA-256 offline. Physical access to the running statistics window is not required for recovery, only for using the recovered password in that window.
